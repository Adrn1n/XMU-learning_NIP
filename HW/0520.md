# 5-45
Sudden release of a transport connection (e.g., abrupt close) can cause data loss because the sender may still have unacknowledged data in its send buffer or in transit. When the connection is immediately terminated, this data may be discarded before the receiver can process it.

TCP’s graceful release (4-way handshake with FIN and ACK segments) ensures both sides confirm they have received all outstanding data before the connection is fully closed, guaranteeing reliable delivery and no loss of user data.

# 5-46
Specific Example:
Suppose host A previously sent a connection request (SYN) that was delayed in the network for a long time. Meanwhile, the connection was released.

Later, this old, invalid SYN finally arrives at host B.
- If only a two-way handshake is used:
  B receives the old SYN and immediately sends back a confirmation (SYN-ACK), thinking A wants to establish a new connection. B allocates resources and waits for data from A, but A never sent this request and will ignore B’s confirmation. So the result is that B wastes resources waiting indefinitely for a connection that doesn’t exist.
- With the three-way handshake:
  B sends SYN-ACK, but A (who did not initiate this connection) will not send the third message (ACK). B receives no final ACK and knows the connection is invalid, so it closes the half-open connection.
Conclusion: The third handshake message ensures that both sides mutually confirm the connection establishment, preventing the acceptance of stale/delayed connection requests and avoiding resource waste.
